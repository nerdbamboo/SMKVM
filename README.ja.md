# SMKVM

[English](README.md) · [한국어](README.ko.md) · **日本語**

キーボードとマウスひとつで複数のコンピュータを。画面の端からポインタを
押し出すと、その画面がどの機械のものであれ次の画面に現れる。一方でコピー
したものは、もう一方で貼り付けられる。

Barrier と Synergy の代わりとして書いた。どちらも保守が止まっていたうえ、
それらで起きていた面倒のほとんどは作りそのものに原因があったからだ。
任意扱いの TLS 層、初見の指紋をそのまま受け入れる仕組み、カーソルが渡る
ときにしかついてこないクリップボード、そしてそれを超えると共有が黙って
止まるサイズの上限。

## できること

- **画面の並べ方は自由。** すべての機械のすべてのモニタが、ひとつの大きな
  デスクトップ上に場所を持ち、ウィンドウでドラッグして並べる。画面が 2 枚
  の機械は、1 枚の長方形ではなく 2 枚の画面として扱われる。
- **一度ペアにし、あとは常に暗号化。** 二台の機械は、両方に表示される
  6 桁の数字を見比べることで一度だけ引き合わされる。その後の接続はすべて
  二つの鍵のあいだの Noise ハンドシェイクで、ペアでない機械はセッション
  どころか返事ももらえない。
- **押しっぱなしは残らない。** 押されているキーとボタンはすべて追跡され、
  ある機械が主導権を失った瞬間に放される -- 画面を渡るとき、リンクが切れた
  とき、UAC のプロンプトが画面を奪ったとき。
- **クリップボードはカーソルではなくコピーについていく。** コピーは何がある
  かを知らせるだけで、中身は貼り付けが起きたときに一かたまりずつ取りに
  行く。だから貼り付けられないスクリーンショットは小さなメッセージ一通分
  で済み、あるサイズから共有が黙って失敗することもない。
- **ファイルも同じ道を通る。** エクスプローラや Nautilus でファイルをコピー
  し、別の機械で貼り付けると、その機械の `~/Downloads/SMKVM` に置かれる。
  貼り付けたときにだけ、同じリンクを通して、一度の貼り付けで引ける量に
  上限を設けて取りに行く。画面をまたぐドラッグはまだない。
- **何をしているかを口に出す。** ステータスファイル、`smkvm status` コマンド、
  そしてウィンドウが、どの機械がつながっていて、画面がどこにあり、どれが
  カーソルを持っているかを示す。設定は変わればそのつど読み直されるので、
  画面を並べ替えた手応えはすぐに返ってくる。

今のところ Windows と Linux (X11)。キーボードとマウスを持つ機械は当面
Windows である必要があり、Linux の機械は受け取る側になる。

## はじめる

一度ビルドする (Rust 1.82 以降):

```
cargo build --release -p smkvm-cli -p smkvm-gui
```

Linux から Windows 向けバイナリを作るなら `cargo xwin build --release --target
x86_64-pc-windows-msvc -p smkvm-cli -p smkvm-gui`。

キーボードとマウスを持つ機械で:

```
smkvm init --role server --listen 192.168.1.10
smkvm pair              # 最初のクライアントを待つ
smkvm run
```

ほかの機械それぞれで:

```
smkvm init --role client --server 192.168.1.10
smkvm pair 192.168.1.10
smkvm run
```

`pair` は両方の機械に同じ 6 桁を表示する。一致したときだけ受け入れること。
あとはどの機械でも `smkvm-gui` を開き、机の上の並びどおりに画面をドラッグ
する。デーモンは数秒でその変更を拾う。

`smkvm status` は何がつながっていて何がどこにあるかを教える。
`smkvm --help` が残りを並べる。

## 置き場所

| | Linux | Windows |
|---|---|---|
| 設定 | `~/.config/smkvm/smkvm.toml` | `%APPDATA%\smkvm\smkvm.toml` |
| 識別情報、ペアにした機械、状態、ログ | `~/.local/share/smkvm/` | `%LOCALAPPDATA%\smkvm\` |

設定は TOML で、手で編集するためのものだ。ウィンドウは自分が受け持つキー
だけを書き直し、あなたが書いたコメントには手を触れない。

## 構成要素

| クレート | 何か |
|---|---|
| `smkvm-layout` | 全体のデスクトップ: すべてのモニタがどこにあり、それぞれの端の先に何があるか |
| `smkvm-proto` | ワイヤフォーマット |
| `smkvm-net` | 識別情報、ペアリング、暗号化されたリンク |
| `smkvm-input` | プラットフォームごとの入力の取り込みと注入 |
| `smkvm-clipboard` | プラットフォームごとのクリップボードの監視・読み取り・提供 |
| `smkvm-core` | 状態機械: カーソルがどこにあるか、何が押されているか、クリップボードが何を出しているか |
| `smkvm-config` | 設定ファイル、ステータスファイル、Barrier からの移行 |
| `smkvm-cli` | `smkvm` デーモンとコマンド |
| `smkvm-gui` | ウィンドウ |

`smkvm-core` の状態機械はソケットもディスプレイも時計も知らない。時刻の
付いたイベントが入り、アクションが出てくる。画面をまたいで押されたままの
修飾キー、貼り付けの途中で消える機械、その先に使えるものがない画面の端 --
そうしたものをハードウェアなしに、どの機械でも正確に試せるのはそのおかげ
だ。

## 手を入れる

```
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings
cargo test --workspace
```

両方のターゲットを、常に。プラットフォーム固有のコードはたいてい片方に
しかない。X11 のテストは `Xvfb` が入っていれば専用のものを起動し、なければ
飛ばす。

設計の理由はコミットメッセージにある。`git log` が、なぜ今の形なのかの記録
として読める。`docs/NOTES.md` にはコードに入っていないことが置いてある。
