# SMKVM

[English](README.md) · **한국어** · [日本語](README.ja.md)

여러 대의 컴퓨터를 키보드와 마우스 하나로. 화면 가장자리 너머로 포인터를
밀면 그 화면이 어느 기계의 것이든 다음 화면에 나타나고, 한쪽에서 복사한
것이 다른 쪽에서 붙여넣어진다.

Barrier와 Synergy를 대신하려고 만들었다. 둘 다 유지보수가 끊긴 데다, 그
둘에서 겪던 문제 대부분이 만들어진 방식 자체에서 비롯됐기 때문이다.
선택 사항이던 TLS 계층, 처음 본 지문을 그대로 받아들이는 방식, 커서가
넘어갈 때만 따라오던 클립보드, 그리고 그 너머로는 공유가 조용히 멈추는
크기 제한.

## 하는 일

- **화면을 어떻게 놓아도 된다.** 모든 기계의 모든 모니터가 하나의 큰
  바탕화면 위에 자리를 갖고, 창에서 끌어다 놓아 배치한다. 화면이 두 개인
  기계는 사각형 하나가 아니라 화면 두 개다.
- **한 번 짝을 맺고, 그 뒤로는 언제나 암호화.** 두 기계는 양쪽에 뜬 여섯
  자리 숫자를 맞춰 보는 것으로 한 번 서로를 소개받는다. 그 뒤 모든 연결은
  두 키 사이의 Noise 핸드셰이크다. 짝이 아닌 기계는 세션은커녕 답조차 받지
  못한다.
- **눌린 채로 남는 것은 없다.** 눌려 있는 키와 버튼은 모두 추적되고, 어떤
  기계가 주도권을 잃는 순간 놓아진다 -- 화면을 넘어갈 때, 연결이 끊길 때,
  UAC 창이 화면을 가져갈 때.
- **클립보드는 커서가 아니라 복사를 따라간다.** 복사하면 무엇이 있는지
  알리기만 하고, 내용은 어딘가에서 붙여넣을 때 한 덩어리씩 가져온다.
  그래서 붙여넣지 않은 스크린샷은 작은 메시지 하나 값이고, 어느 크기부터
  공유가 조용히 실패하는 일도 없다.
- **파일도 같은 길로, 끌어다 놓아도.** 탐색기나 Nautilus에서 파일을 복사해
  다른 기계에서 붙여 넣거나, 한 화면의 가장자리 밖으로 끌고 가 다른 화면에서
  놓으면, 어느 쪽이든 그 기계의 `~/Downloads/SMKVM`에 도착한다. 같은 링크로,
  붙여 넣을(놓을) 때 가져오며, 한 번에 가져오는 양에는 한도가 있다. Windows
  에서는 놓은 자리에도 떨어지고, 어디에서나 도착한 파일은 클립보드에 올라가
  있어 붙여 넣기로 놓을 수 있다.
- **무엇을 하고 있는지 말해 준다.** 상태 파일, `smkvm status` 명령, 그리고
  창이 각각 어떤 기계가 연결돼 있고 화면이 어디에 있으며 커서를 누가 쥐고
  있는지 보여 준다. 설정은 바뀌면 곧바로 다시 읽으므로, 화면을 옮긴 것이
  바로 느껴진다.

오늘은 Windows와 Linux(X11). 키보드와 마우스를 쥐는 기계는 당분간
Windows여야 하고, Linux 기계는 받는 쪽이다.

## 시작하기

한 번 빌드한다 (Rust 1.82 이상):

```
cargo build --release -p smkvm-cli -p smkvm-gui
```

Linux에서 Windows 바이너리를 만들려면 `cargo xwin build --release --target
x86_64-pc-windows-msvc -p smkvm-cli -p smkvm-gui`.

키보드와 마우스를 쥔 기계에서:

```
smkvm init --role server --listen 192.168.1.10
smkvm pair              # 첫 클라이언트를 기다린다
smkvm run
```

나머지 기계마다:

```
smkvm init --role client --server 192.168.1.10
smkvm pair 192.168.1.10
smkvm run
```

`pair`는 양쪽에 같은 여섯 자리를 보여 준다. 같을 때만 수락한다. 그 다음
아무 기계에서나 `smkvm-gui`를 열고 화면들을 책상 위 배치대로 끌어다
놓는다. 데몬은 몇 초 안에 그 변경을 집어 든다.

`smkvm status`는 무엇이 연결돼 있고 어디에 있는지 알려 준다.
`smkvm --help`가 나머지를 보여 준다.

## 어디에 무엇이 있나

| | Linux | Windows |
|---|---|---|
| 설정 | `~/.config/smkvm/smkvm.toml` | `%APPDATA%\smkvm\smkvm.toml` |
| 신원, 짝지은 기계, 상태, 로그 | `~/.local/share/smkvm/` | `%LOCALAPPDATA%\smkvm\` |

설정은 TOML이고 직접 편집하라고 만든 것이다. 창은 자기가 맡은 키만 다시
쓰고 당신이 적은 주석은 건드리지 않는다.

## 구성

| 크레이트 | 무엇인가 |
|---|---|
| `smkvm-layout` | 전체 바탕화면: 모든 모니터가 어디에 있고 각 가장자리 너머에 무엇이 있는지 |
| `smkvm-proto` | 와이어 포맷 |
| `smkvm-net` | 신원, 페어링, 암호화된 링크 |
| `smkvm-input` | 플랫폼별 입력 캡처와 주입 |
| `smkvm-clipboard` | 플랫폼별 클립보드 감시, 읽기, 내주기 |
| `smkvm-core` | 상태 기계: 커서가 어디 있는지, 무엇이 눌려 있는지, 클립보드가 무엇을 내놓고 있는지 |
| `smkvm-config` | 설정 파일, 상태 파일, Barrier로부터의 이전 |
| `smkvm-cli` | `smkvm` 데몬과 명령 |
| `smkvm-gui` | 창 |

`smkvm-core`의 상태 기계는 소켓도 디스플레이도 시계도 모른다. 시각이 붙은
이벤트가 들어가고 동작이 나온다. 화면을 넘어가는 동안 눌려 있는 수정 키,
붙여넣기 도중에 사라지는 기계, 너머에 쓸 것이 없는 화면 가장자리 같은
것을 하드웨어 없이 어느 기계에서나 정확히 시험할 수 있는 것은 그
덕분이다.

```
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo clippy --workspace --all-targets --target x86_64-pc-windows-msvc -- -D warnings
cargo test --workspace
```

`Xvfb`가 설치돼 있으면 전용으로 하나 띄우고, 없으면 건너뛴다.

설계의 이유는 커밋 메시지에 있다. `git log`가 왜 지금 모습인지에 대한
기록으로 읽힌다. `docs/NOTES.md`에는 코드에 없는 것이 담겨 있다.
